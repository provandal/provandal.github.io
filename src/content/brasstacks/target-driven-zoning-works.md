<p>Thanks to EMC’s DJ Brown and some help from Blayne Rawsky at Brocade, we finally have <a href="/brasstacks/introducing-target-driven-zoning-tdz/" target="_self">TDZ</a>&#0160;running in the lab.&#0160; The first peer zone was successfully registered on 3:55 PM EDT on Thursday April 4<sup>th </sup>2013. </p>
<p>&#0160;</p>
<p><strong>Test configuration</strong></p>
<p>The test configuration was deliberately kept small and is shown below.</p>
<p>&#0160;
<a class="asset-img-link" href="/brasstacks/target-driven-zoning-works/6a013487ed263f970c017c388fd1fa970b.jpg" style="display: inline;"><img alt="One" border="0" class="asset  asset-image at-xid-6a013487ed263f970c017c388fd1fa970b image-full" src="/brasstacks/target-driven-zoning-works/6a013487ed263f970c017c388fd1fa970b.jpg" title="One" /></a></p>
<p>The Server is a Cisco UCS C Series server running SLES11SP2 with a
QLogic 8GHBA installed in it.&#0160; </p>
<p>The switch is a Brocade 6505 that is running a special test version of&#0160;FOS with rudimentary TDZ support.</p>
<p>The Storage is an EMC VMAX that is running a special TDZ capable debug&#0160;version of Enginuity.&#0160; </p>
<p><strong>&#0160;</strong></p>
<p><strong>The protocol</strong></p>
<p>As shown in the xgig trace below, as soon as the link came&#0160;up between the Storage and the Switch, the storage port transmitted a GAPZ &#0160;(Get Active Peer Zone, command = 012A) and the&#0160;switch rejected this request because there was no peer zone registered&#0160;yet.&#0160; This is normal and expected&#0160;behavior the first time a storage port initializes.</p>
<p>
<a class="asset-img-link" href="/brasstacks/target-driven-zoning-works/6a013487ed263f970c017eea332224970d.jpg" style="display: inline;"><img alt="Two" border="0" class="asset  asset-image at-xid-6a013487ed263f970c017eea332224970d image-full" src="/brasstacks/target-driven-zoning-works/6a013487ed263f970c017eea332224970d.jpg" title="Two" /></a><br /><br /></p>
<p>The storage then transmits AAPZ (Add/Replace Active Peer&#0160;Zone, command = 022B).&#0160; The storage uses<br />this command to register the peer zone with the switch.&#0160; The result of this command is shown below in<br />the cfgshow output. </p>
<p>
<a class="asset-img-link" href="/brasstacks/target-driven-zoning-works/6a013487ed263f970c017d42beeab6970c.jpg" style="display: inline;"><img alt="Three" border="0" class="asset  asset-image at-xid-6a013487ed263f970c017d42beeab6970c image-full" src="/brasstacks/target-driven-zoning-works/6a013487ed263f970c017d42beeab6970c.jpg" title="Three" /></a><br /><br /></p>
<p>Notice the zone name of “PRZ_X0_500009730005FD1C”.&#0160; The zone members are the WWPNs of the VMAX&#0160;port (starting with 50:00) and the QLogic HBA (starting with 21:00).&#0160; This zone was created by the switch in&#0160;response to the AAPZ command that was sent by the VMAX port.&#0160; </p>
<p>Another important point to note in the xgig trace is the PLOGI&#0160;and PRLI after the RSCN.&#0160; These requests<br />were from the host and I’ll simply point out that the QLogic HBA automatically&#0160;generated these login requests after it received an RSCN.&#0160; The RSCN was generated by the switch in&#0160;response to the zoning change that was initiated by the VMAX registering a peer&#0160;zone.&#0160; The fact that the host&#0160;automatically detected the zoning change and logged into the storage port is&#0160;due to the way that FC Discovery works and TDZ leverages this behavior so that&#0160;it can function properly even though no changes were made on the HBA to allow&#0160;the TDZ functionality to operate correctly.&#0160;&#0160;</p>
<p>&#0160;</p>
<p><strong>Next steps</strong></p>
<p>The next steps are to scale up the number of ports and&#0160;prepare for a demonstration at EMC World in May.&#0160; I’ll provide more detail about my sessions&#0160;and when you can see TDZ working in a subsequent post.&#0160; </p>
<p>In regards to product plans for including the TDZ&#0160;functionality, there are none.&#0160; However, I’m&#0160;hoping that if we get enough positive feedback on this blog post and at EMC&#0160;World that we’ll be able to convince both Brocade and EMC to add it to our&#0160;roadmaps and into your environments as soon as possible.&#0160; </p>
Thanks for reading!
