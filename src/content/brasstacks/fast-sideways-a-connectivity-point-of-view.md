<p>Although&#0160;I mentioned this functionality in a previous <a href="/brasstacks/virtual-storage-networks-part-2-requirements-for-multi-tenant-storage/" target="_self">blog post</a>, the impact that this type of use case will have on connectivity automation is so significant that it deserves to have it&#39;s own post. &#0160;&#0160;</p>
<p>The first time I heard the FAST Sideways concept mentioned publicly was by Brian Gallagher during an EMC World 2013 keynote.&#0160; Brian and Steve Todd then talked about the topic in just a bit more detail during an&#0160;<a href="http://stevetodd.typepad.com/my_weblog/2013/05/brian-gallagher-backstage.html" target="_self">EMCBackstage interview</a>.&#0160; Although I believe there will be a team of folks at EMC World this year taking about this concept in general, I’ll say the following about it from a Connectivity Automation perspective.</p>
<p><strong>Fully Automated Storage Tiering (FAST)</strong>&#0160;allows blocks of storage to be moved between different tiers of storage (e.g., Flash, FC, SAS) on the same Array.&#0160; These placement decisions are driven by the FAST Engine that runs on the Array’s Service Processor (in the case of VMAX) which makes use of user defined policies.&#0160; Because the placement decisions do not impact SCSI connectivity (e.g., LUN, LU ID), these changes are effectively invisible to the host and do not require connectivity layer changes.</p>
<p><strong>FAST Sideways</strong>&#0160;can be thought of as an extension to FAST but instead of operating within a single array, volumes could be moved from one array to another.&#0160; These placement decisions will probably need to be driven by a FAST Federation engine that logically operates at a layer above the FAST engines running on each array.&#0160; This FAST Federation engine will also probably make use of user defined policies to assist in placement decisions but unlike the FAST engine, it will also need to interact with connectivity elements (e.g., FC switches or Virtual Networks) in order to configure&#0160;both&#0160;array to array and host to array connectivity as shown in the following diagram set.</p>
<p><a class="asset-img-link" href="/brasstacks/fast-sideways-a-connectivity-point-of-view/6a013487ed263f970c01a5119e46b2970c.jpg" style="display: inline;"><img alt="Nine" border="0" class="asset  asset-image at-xid-6a013487ed263f970c01a5119e46b2970c image-full img-responsive" src="/brasstacks/fast-sideways-a-connectivity-point-of-view/6a013487ed263f970c01a5119e46b2970c.jpg" title="Nine" /></a></p>
<p>The diagram above contains two physical hosts, a host facing fabric, two storage arrays and a storage fabric at three different phases (i.e., Beginning, Intermediate, and Completed) of a FAST Sideways operation.&#0160; The host facing and storage fabrics could either utilize completely different approaches to connectivity (e.g., the host facing fabric could be Fibre Channel (FC) based while the Storage fabric could be a VXLAN based Over The Top (OTT) Virtual Network).&#0160; Although not shown in the diagram, both could utilize the same physical fabric.</p>
<p><strong>FAST Sideways workflow</strong>&#0160;– In this case, the user or the FAST Federation engine decides to move&#0160;<strong>Host 2</strong>&#0160;to&#0160;<strong>Array 2</strong>&#0160;because&#0160;<strong>Array 1</strong>&#0160;is very busy and&#0160;<strong>Array 2</strong>&#0160;is nearly idle. When this happens, three high level actions would need to occur:</p>
<ol>
<li>Establish connectivity between&#0160;<strong>Array 1</strong>&#0160;and&#0160;<strong>Array 2</strong>;</li>
<li>Allow&#0160;<strong>Host 2</strong>&#0160;to access its volumes on&#0160;<strong>Array 2</strong>; and</li>
<li>Remove connectivity between&#0160;<strong>Array 1</strong>&#0160;and&#0160;<strong>Array 2</strong>&#0160;once the data has been copied.</li>
</ol>
<p>Each of the phases is described in more detail below.</p>
<p><strong>Beginning</strong>&#0160;– The Beginning portion of the diagram illustrates&#0160;<strong>Host 1 (</strong>Blue) and&#0160;<strong>Host 2 (</strong>Red) accessing different volumes (e.g., “Blue” and “Red” respectively) on the same storage array.</p>
<p><strong>Intermediate</strong>&#0160;– This diagram illustrates that connectivity has been established between&#0160;<strong>Array 1</strong>&#0160;and&#0160;<strong>Array 2</strong>.&#0160; Once this connectivity has been established, volume replication may begin from&#0160;<strong>Array 1</strong>&#0160;to&#0160;<strong>Array 2</strong>&#0160;via any means available (e.g., ORS, SRDF, etc).&#0160; Also at this point connectivity between&#0160;<strong>Host 2</strong>&#0160;and&#0160;<strong>Array 2</strong>&#0160;could be established.&#0160; Once this connectivity has been established,&#0160;<strong>Host 2</strong>&#0160;will need to discover&#0160;<strong>Array 2</strong>&#0160;via a protocol specific mechanism that is described in a later section.&#0160; Once Array 2 has been discovered, the volumes may be made available to the operating system via any means available (e.g., ALUA).&#0160; At this point&#0160;<strong>Host 2</strong>&#0160;could begin to access its storage on&#0160;<strong>Array 2</strong>&#0160;(i.e., if ORS is in use). &#0160; &#0160; &#0160;</p>
<p><strong>Completed</strong>&#0160;– This diagram illustrates&#0160;<strong>Host 2</strong>&#0160;accessing its Storage on&#0160;<strong>Array 2</strong>&#0160;and the connection between&#0160;<strong>Array 1</strong>&#0160;and&#0160;<strong>Array 2</strong>&#0160;has been removed.</p>
<p>All of that in mind, you can think of FAST sideways as one possible way to remediate chronic issues with an inability to meet IOPS and RT objectives.</p>
